## Архитектура

C# / .NET 8, WPF (`net8.0-windows`, x64). Главного окна нет, только иконка в трее
(`Hardcodet.NotifyIcon.Wpf`). Орфография — `WeCantSpell.Hunspell` (чистый C#).

```
src/RuType
  Interop/   Win32: KeyboardHook (WH_KEYBOARD_LL), MouseHook (WH_MOUSE_LL),
             KeyTranslator (клавиша -> символ через раскладку, ToUnicodeEx),
             Replacer (backspace + Unicode через SendInput), LayoutSwitcher
             (детект ru/en HKL, WM_INPUTLANGCHANGEREQUEST), ExclusionManager
             (чёрный список приложений, окна с правами выше наших, поля паролей),
             NativeMethods.
  Core/      InputProcessor (конечный автомат ввода: буфер слова, границы, хоткеи,
             сырой сегмент клавиш), Analyzer (приоритеты решения), Dictionaries
             (Hunspell ru/en + частоты + словари-дополнения + пользовательские
             списки + fuzzy-индекс), NgramModel, TokenClassifier, CandidateRanker,
             EditDistance (Дамерау-Левенштейн), WordBuffer, LayoutMap, CaseHelper,
             SuggestionCounter, LearnLog, Log, SelfTest, Eval и служебные пробы.
  Config/    AppConfig (схема config.json), ConfigStore, AutostartManager.
  Tray/      TrayApp, SettingsWindow, SuggestionWindow, RuleDialog,
             DarkTheme.xaml (шаблоны контролов тёмной темы), Theme.cs.
  App.xaml.cs  композиционный корень.
```

## Путь нажатия клавиши

1. Низкоуровневый хук клавиатуры получает нажатие. Инъецированный ввод (наш собственный,
   флаг `LLKHF_INJECTED`) отбрасывается сразу, это защита от самозацикливания. Хуки
   клавиатуры и мыши живут на отдельном потоке «RuType hooks» со своим циклом сообщений
   (см. «Потоки»), обработка нажатия и инъекция идут там же.
2. `InputProcessor` переводит клавишу в символ через раскладку активного окна. Буквы и
   цифры копятся в буфер слова; параллельно копится «сырой сегмент» нажатых клавиш
   (vk, scan, Shift, CapsLock), чтобы позже перевести его через любую раскладку Windows.
3. Пробел, Enter, Tab или знак препинания — граница слова. Слово уходит в `Analyzer`.
4. Если нужна замена, граничная клавиша подавляется (хук возвращает 1), а через
   Dispatcher потока хуков планируется инъекция: N backspace, новый текст, сама граница.
   Enter и Tab впечатываются как виртуальные клавиши, а не Unicode (Unicode-инъекция
   переводов строки ненадёжна). Для смены раскладки окну сначала посылается запрос смены
   языка. Перед инъекцией проверяется, что активное окно то же, что в момент решения;
   число вставленных `SendInput` событий сверяется, при недоборе состояние набора
   сбрасывается.
5. Клик мышью, стрелки, Home/End, смена активного окна, сочетания с Ctrl/Alt/Win
   сбрасывают буфер: каретка больше не там, где мы думаем.

Границу подавляем и впечатываем сами намеренно: если стирать «слово плюс пробел» после
того, как пробел уже ушёл в приложение, гонка с недоставленным пробелом теряла
backspace и оставляла артефакты вида «ппривет».

## Приоритеты решения

`Analyzer.Analyze` идёт по цепочке, первое сработавшее правило выигрывает:

1. **Стоп-слово** — руки прочь, абсолютный иммунитет.
2. **Правило замены** из `rules.txt` — жёсткая подстановка.
3. **Мой словарь** — слово корректное, не трогаем.
4. **Детект раскладки** (перед опечаткой! иначе `ghbdtn` попало бы под нечёткую правку).
5. **Смешанная раскладка**: `привеn` → `привет`.
6. **Опечатка**.

## Исправление опечаток

- **Hunspell как вето.** Если слово есть в словаре (Hunspell ru + словари-дополнения +
  мой словарь), его не трогаем. Морфология решает «ошибка или нет», и это главная причина
  выбора Hunspell вместо частотных списков: во флективном русском частотный список
  словоформ слаб как оракул валидности, редкие формы шли под ложную правку.
- **Кандидаты**: Hunspell `Suggest` + аффиксный словарь-дополнение + плоский словарь-
  дополнение + fuzzy-поиск по частотному списку (306k форм, индекс по двухсимвольному
  префиксу). Последний закрывает пробелы `Suggest`, например `програма` → `программа`.
- **Фильтр по расстоянию** Дамерау-Левенштейна (по умолчанию не больше 1).
- **Ранжирование**: балл = естественность по триграммной модели + логарифм частоты.
  Замена только при уверенном отрыве лучшего кандидата от второго (`typo.score_gap`).
  Единственный кандидат проходит всегда. Резервный путь при выключенной модели —
  частотный доминант (`dominance_ratio`, `min_frequency`).
- **Слово не расщепляется на два.** Hunspell для неизвестного современного слова
  предлагает разбивку на известные части («переиспользовать» → «пере использовать»);
  это правка расстояния 1 и она проходила фильтр. Кандидаты с пробелом отбрасываются.
- Регистр результата подгоняется под ввод: ВСЕ ПРОПИСНЫЕ, Первая прописная, строчные.

Опыт настройки: ложная правка почти всегда означает, что слова просто нет в словаре.
Лечится словарём-дополнением, а не порогами: пороги режут вслепую и по хорошим правкам
тоже («мочалку» вместо «модалку» — это нормальное русское слово с хорошим баллом, модель
естественности здесь ничего не различает).

## Автопереключение раскладки

- Работает только по буквам и только для слов длиной от `layout.min_word_length`
  (по умолчанию 4): короткие слова случайно совпадают со словами другой раскладки.
- Условие смены: слово невалидно в текущем языке и валидно в другом. Русская
  валидность = Hunspell + мой словарь + словари-дополнения; английская = Hunspell +
  `en_extra`. Валидность всегда проверяется по строчной форме, поэтому имена собственные
  (в Hunspell они только с заглавной: `Америка`, `Иран`) в чужой раскладке не
  перекладываются. Это осознанно: расширение оракула на имена поднимает долю ложных
  срабатываний; нужное имя можно дописать в «Мой словарь».
- **Технические токены защищены** (`layout.protect_technical`): аббревиатуры (USB, API),
  бренды с заглавной внутри (GitHub, iPhone), слова с цифрами (win10).
- **Раскладка плюс опечатка** (`layout.fix_typo_on_switch`): `gbhdtn` → перекладка
  `пирвет` невалидна → тот же корректор опечаток даёт `привет`. Порог длины отдельный и
  выше обычного (`fix_typo_min_length`, по умолчанию 4): на трёхбуквенных токенах эта
  ветка почти всегда портит текст (`tcp` → «ест», `php` → «зря»), с четырёх окупается.
- **Домены и имена файлов** (`layout.switch_known_domain_ext`): `пщщпдуюсщь` → `google.com`,
  `куфвьуюьв` → `readme.md`. Словарём такие токены не проверить, опора на структуру
  `имя.ext` с известным TLD или расширением. Клавиша точки в русской раскладке даёт
  букву `ю`, а русские слова не оканчиваются на `ю` плюс кластер вроде `юсщь`.

### Слова со знаками-буквами

В русской раскладке на клавишах знаков стоят буквы: `;` = `ж`, `,` = `б`, `.` = `ю`,
`[` = `х`, `]` = `ъ`, `'` = `э`. Буквенный буфер рвётся на таком знаке, поэтому слово
целиком чинит **сырой сегмент клавиш** на пробеле или Enter, тремя стратегиями по порядку:

1. Прогон целиком: `ghjljk;bnm` → `продолжить`, `,fylbn` → `бандит`.
2. Отрезание хвостовой пунктуации (до 3 клавиш): сначала по целевому рендеру
   (`ghjljk;bnm?` → `продолжить,`), затем по текущему (`ghbdtn.` → `привет.`).
3. Разрез по знакам между словами: `ghbdtn,rfrjq` → `привет,какой`. Каждый кусок
   длиной от порога должен пройти то же вето (валиден в целевой раскладке, невалиден в
   текущей), и хотя бы один такой кусок обязателен.

Решение по префиксу на самом знаке-букве гасится (иначе `ghjljk;bnm` давал `продал;ить`),
а знак-граница при смене раскладки печатается целевым рендером: `ghbdtn/` — это
`привет.`. Однобуквенные правила на знаке-границе не применяются: одиночная буква —
префикс многих слов, а знак может быть буквой-продолжением (`d',` = `вэб`).

## Словари

Все словари лежат в `dict/`.

| Файл | Что это | Роль |
|---|---|---|
| `ru_RU.dic/.aff`, `en_US.dic/.aff` | Hunspell | оракул «слово существует?», кандидаты |
| `ru-300k.txt` | частотный список (OpenSubtitles, топ-300k) | ранжирование, fuzzy-кандидаты, обучение триграмм |
| `ru_extra.txt` | ~6.9k современных слов и англицизмов, «слово частота» | вето валидности и кандидаты для слов, которых нет в Hunspell |
| `ru_extra.dic` | леммы с аффиксными флагами `ru_RU.aff` | вся парадигма склонения сразу |
| `en_extra.txt` | тех-токены и аббревиатуры, которых нет в `en_US` | защита от перекладки en→ru и перекладка ru→en |

**Почему два словаря-дополнения.** Плоский список форм не просто не помогал, а портил:
неполная парадигма делала форму из списка единственным кандидатом на расстоянии 1
(`пасхалках` → `пасхалка`). Аффиксный `ru_extra.dic` (`модалка/I`, `навбар/K`,
`фейковый/AES`, `задеплоить/BLRW`) отдаёт морфологии всю парадигму. Формат `.dic` не
знает комментариев, поэтому строки с `#` вырезаются при загрузке, счётчик в первой
строке пересчитывается автоматически.

**Коллизии в `en_extra`.** Русское слово, чья перекладка попадает в список, начнёт ложно
уходить в латиницу: так были выброшены `ctr` (← «сек»), `ltv` (← «дем»), `tls` (← «еды»).

**Пользовательские списки** в `data/` — это три разных механизма:

- `stopwords.txt` — абсолютный иммунитет, проверяется раньше правил и глушит даже их.
  Слово при этом не становится валидным.
- `my_words.txt` — расширение словаря: слово валидно, участвует в детекте раскладки,
  проверяется после правил.
- `rules.txt` — `что = на что`, без учёта регистра; ключ может содержать знаки, потому что
  сверяется и с сырым прогоном клавиш (`;jhbr = жорик`).

## Триграммная модель

`NgramModel` — символьная триграммная модель русского слова (сглаживание add-1). Слово
оборачивается маркерами начала и конца, балл — **средний** логарифм вероятности на
триграмму (сумма штрафовала бы длину, и короткие кандидаты-удаления всегда выигрывали).
Решения принимаются по разнице баллов кандидата и исходного слова, а не по абсолюту.

Обучение (`ngram.weight_by_frequency`, по умолчанию включено) идёт по частотному списку
с весом по частоте: счётчики воспроизводят корпусную встречаемость буквосочетаний, и
разрыв между настоящим словом и мусором-раскладкой заметно больше, чем при обучении по
словарю (каждая лемма один раз). Модель кешируется в `data/ngram_ru.cache`; смена режима
или файла-источника перестраивает кеш. Строится на старте, а не в потоке хука; смена
режима в настройках пересобирает модель в фоновой задаче, пока работает прежняя.

## Горячие клавиши

**Pause** (`layout.hotkey_undo_vk`) контекстная:

- если по последнему слову была автоправка — циклически переключает исправленное и
  исходное; откат учитывается счётчиком для окна слова;
- иначе перебивает раскладку набираемого «сырого» сегмента (буквы и знаки, через реальную
  раскладку Windows) — хоть с одного символа, повторное нажатие возвращает обратно;
- если набора нет — перекладывает последнее завершённое слово вместе с хвостом
  разделителей («слово, » тоже переживает).

Ручная перекладка сегмента не переопределяется на границе: без этого пробел после
«Pause → обратно» снова включал авто-детект и возвращал слово.

**Scroll Lock** (`layout.hotkey_suggest_vk`) открывает окно слова вручную. Оба хоткея
меняются в настройках.

## Окно слова и пользовательские списки

`SuggestionWindow` всплывает у курсора и не крадёт фокус. Появляется по слову, правку
которого пользователь откатил N раз (`suggestions.threshold`), или вручную по хоткею.
Кнопки: «Менять на X» (правило смены раскладки одним кликом), «Не трогать это слово»
(стоп-слово), «Правило…» (диалог), «Закрыть». Закрывается и кликом мимо окна: окно не
активируется, поэтому событие деактивации не приходит, а захват мыши съел бы клик
приложению. Используется пассивный хук мыши: клик вне рамки закрывает окно, сам клик
проходит дальше.

## Исключения и безопасность ввода

- **Чёрный список приложений** по имени процесса активного окна.
- **Окна с правами выше наших.** UIPI не пропускает `SendInput` в процесс с более высоким
  уровнем целостности (запущенный от администратора), а граничную клавишу мы подавляем
  раньше, чем вставляем текст. Поэтому при смене активного окна читается уровень
  целостности его процесса; окно выше нашего (или с нечитаемым токеном) исключается
  целиком, включая хоткеи.
- **Поля паролей** определяются тремя путями. На каждую клавишу: Win32-детект
  (`ES_PASSWORD` у нативного Edit) и флаг из подписки на смену фокуса UI Automation
  (браузеры, Electron; подписка регистрируется из фонового потока, обработчик работает на
  потоке UIA). На границе слова и на Pause, до любого действия и логирования: прямой
  запрос `FocusedElement.IsPassword`. Он кросс-процессный и дорогой, поэтому кешируется по
  (активное окно, hwnd фокуса, версия событий фокуса) на 1.5 с, но кеш сбрасывается всем,
  что может увести фокус: событием UIA, Tab/Enter, Ctrl/Alt/Win-сочетаниями, кликом мыши.
  Одного ключа мало: в браузере hwnd фокуса один на все поля страницы, и «не пароль»,
  закешированное на Tab из поля логина, иначе жило бы в поле пароля. Сценарий закреплён
  в `--selftest`.
- **Отладочный лог не пишет отдельные нажатия**: на этом шаге полная проверка поля пароля
  ещё не выполнена. Слово попадает в лог только на границе, после проверки.
- **Ctrl/Alt/Win-сочетания — команды, не текст.** `ToUnicodeEx` при зажатом Alt всё равно
  возвращает символ (табуляцию для Alt+Tab, перевод строки для Alt+Enter), без отсечки
  Alt+Tab с невалидным словом в буфере срабатывал как граница.
- **Смена активного окна** проверяется раньше хоткеев: иначе перекладка слова из прежнего
  окна впечатывалась в новое.

## Надёжность: решения, к которым пришли через грабли

- `SendInput` требует `cbSize = Marshal.SizeOf<INPUT>()` (40 на x64); с захардкоженными
  28 он молча возвращает 0.
- **Потоки.** Обработчик LL-хука выполняется в цикле сообщений потока, который его
  установил. Пока хуки жили на UI-потоке, любая его заминка (открытие окна настроек,
  пересборка модели) тормозила ввод во всей системе. Теперь оба хука, их watchdog,
  `InputProcessor` и инъекция живут на отдельном STA-потоке с Dispatcher. UI-поток
  (трей, окна, звук, лог правок) получает события через `BeginInvoke` и никогда не ждёт
  поток хуков синхронно. Разделяемое состояние: анализатор читает собственный снимок
  настроек (`ConfigStore.Clone`, новый передаётся при сохранении), пользовательские списки
  и n-gram подменяются ссылкой целиком.
- Windows молча снимает низкоуровневый хук, если обработчик один раз превысил
  `LowLevelHooksTimeout` (300 мс). Оба хука (клавиатуры и мыши) переустанавливаются по
  таймеру каждые 30 с; без хука мыши клик перестал бы сбрасывать набор. Ошибка установки
  любого хука — исключение, запись в лог и сообщение пользователю. Длительность
  обработчика измеряется, медленные вызовы пишутся в отладочный лог.
- Инъекция планируется через Dispatcher потока хуков с приоритетом Normal: клавиши,
  набранные между возвратом из хука и `SendInput`, иначе попадали под наши backspace.
- Отладочный лог асинхронный: строка кладётся в очередь, файл дописывает фоновый поток.
- Сессионной памяти «не трогать» нет: она раздражала, слова «застревали». Одноразовый
  пропуск только если правка реально стёрта и слово перенабрано (loop-guard). Постоянное
  «не трогать» — через окно слова.
- Сырой сегмент длиннее 64 клавиш помечается непригодным, а не обрезается с начала.
- Новый Блокнот Windows 11 имеет свой автокорректор и конфликтует с любым внешним.

## Данные и логи

Программа портабельная: всё в `data/` рядом с exe, ничего в `%APPDATA%` и реестре, кроме
ключа автозапуска (`HKCU\...\Run`, если включён).

- `config.json` — настройки (snake_case, новые поля дописываются при старте). Запись
  атомарная: временный файл с flush на диск, затем переименование поверх. При чтении
  значения нормализуются (null-секции → дефолты, числа → допустимые диапазоны). Нечитаемый
  файл копируется в `config.json.broken-ГГГГММДД-ЧЧММСС`, программа стартует на дефолтах,
  предупреждает и на старте конфиг не пересохраняет.
- `my_words.txt`, `stopwords.txt`, `rules.txt` — пользовательские списки.
- `ngram_ru.cache` — кеш триграммной модели.
- `corrections.jsonl` — лог правок и откатов (`learning.enabled`, по умолчанию выключен). Это не keylog: только
  события автозамены («что заменили на что») и отказов (откат хоткеем или стирание с
  перенабором), без потока набора, буфера обмена и содержимого окон; в исключённых
  контекстах не пишется. Нужен, чтобы настраивать качество на реальных данных.
- Отладка: пустой файл `data/debug.on` включает `data/rutype_debug.log`.

## Сборка и разработка

Нужен .NET 8 SDK.

```
dotnet build RuType.sln -c Debug
dotnet run --project src/RuType/RuType.csproj
```

Служебные режимы (все headless, без хука и трея):

| Команда | Что делает |
|---|---|
| `--selftest` | словарные пробы Analyzer и сценарии полного пути ввода на фейковой клавиатуре; отчёт в `%TEMP%\rutype_selftest.txt` |
| `--eval` | качество на golden-наборе: FIX accuracy («вход → выход») и KEEP FP-rate («не трогать»); фикстуры в `Eval.cs` |
| `--check слово…` | вердикты всех оракулов по словам (или `--check @файл`) |
| `--margin-probe [corrections.jsonl]` | что даст порог естественности на реальном логе правок |
| `--ngram-probe` | сравнение режимов обучения триграмм |
| `--dump-unknown [minFreq]`, `--filter-unknown in out` | генерация словаря-дополнения: слова частотного списка, неизвестные Hunspell |
| `--settings [N] [--offscreen]` | окно настроек без хука и мьютекса (можно рядом с работающей копией); N — страница |

`InputProcessor` тестируется headless: перевод клавиш, раскладка, модификаторы, активное
окно — подменяемые функции; `SelfTest.FakeKeyboard` эмулирует QWERTY/ЙЦУКЕН и «экран».
Грабли живут именно там, Analyzer-фикстуры их не видят, поэтому каждый регресс
закрепляется сценарием ввода.

Снимок окна настроек для документации: `tools\settings-shot.ps1 -Page 0 -Out docs\settings.png`
(окно открывается за экраном и рендерится через `PrintWindow`, без кликов и захвата фокуса).

### Портабл-релиз

```
dotnet publish src/RuType/RuType.csproj -c Release -o dist/RuType
```

Параметры публикации (single-file, self-contained, ReadyToRun, без символов) заданы в
csproj и действуют только при `dotnet publish`. Две особенности:

- Нативные dll WPF не упаковываются в exe (`IncludeNativeLibrariesForSelfExtract=false`):
  при самораспаковке они живут во временной папке, чистильщики её сносят, и программа
  падала с `DllNotFoundException` при выходе. Пять `*_cor3.dll` лежат рядом с exe.
- Публиковать нужно начисто: повторная инкрементальная публикация видит актуальный
  бандл и не докладывает нативные dll в выходную папку. `deploy.ps1 -Publish` сам чистит
  `bin/obj Release`, затем копирует релиз в целевую папку, не трогая `data/`.

Крупные словари single-file теряет из выходной папки, поэтому csproj докопирует `dict/`
отдельным таргетом после публикации. Иконка exe — `assets/icon.ico`, версия — `<Version>`
в csproj. Один экземпляр гарантирует мьютекс `Local\RuType_SingleInstance`.

### Тема интерфейса

Шаблоны контролов (скроллбар, поле ввода, тумблер, радиокнопка, кнопки, пункт
навигации, подсказка) лежат в `Tray/DarkTheme.xaml` и подключены в `App.xaml`; те же
цвета продублированы кистями в `Theme.cs` для окон, которые строятся в коде. Менять
синхронно. В своём шаблоне `TextBox` не дублировать `Padding` отступом у
`PART_ContentHost`: `TextBoxView` применяет его сам.
